# DKMS 0.1.2 upstream-audit validation

## Audited fixes

- Mesh software-crypto fallback now rejects only `SET_KEY`; defensive
  `DISABLE_KEY` calls succeed as required by mac80211.
- RX cancellation runs before URB killing and again after all callbacks are
  quiesced, preventing a racing completion from leaving delayed retry work
  queued during teardown.

## Build and activation

All five modules built cleanly against `6.12.47+rpt-rpi-v8`. Installed and
loaded source versions matched. Automatic recovery restored an established
open channel-1 HT20 mesh in five seconds without a kernel or USB error.

## Churn

Twenty strict cycles passed 20/20 for:

- join and peer establishment;
- cold first contact in both directions;
- multicast delivery in both directions;
- populated HWMP paths on both endpoints.

Peer establishment took 117--137 ms. No USB error was logged.

## RX retry and teardown

A disposable build applied `usb_rx_submit_failure.patch`; production DKMS
artifacts were not modified.

Eight pre-submit `-EPROTO` failures were consumed. The success bitmap reached
`15` (`0xf`), proving that every RX control block submitted successfully after
the injected failures. Both 40-packet directional ping runs passed.

The injector was then set to 100,000 failures. Immediately before full stack
removal, 99,980 remained, proving delayed retry work was active. Unload plus
production reload took 857 ms and produced no warning, Oops, UAF, refcount, or
workqueue-after-free signature. Loaded production `rtw_usb` provenance matched
the installed DKMS 0.1.2 artifact. Mesh recovery completed and both 10-packet
directional ping runs passed.

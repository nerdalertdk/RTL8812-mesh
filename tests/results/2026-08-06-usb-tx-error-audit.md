# USB TX error and teardown audit — 2026-08-06

## Scope

This audit covers the RTL8812AU rtw88 USB transmit path after the validated
DKMS 0.1.4 symmetric mesh tests. It is source evidence for DKMS 0.1.5, not yet
hardware qualification of that version.

## Findings

The inherited TX path transferred skb/context ownership to an URB completion
callback but did not handle every path on which that callback cannot or must
not claim success:

1. A synthetic aggregate transfer skb was inserted into mac80211's TX-status
   queue alongside the original frames. Normal completion reported that
   driver-owned buffer as a frame with an uninitialized control block, and
   submission failure passed it to mac80211's TX-free path.
2. `rtw_usb_tx_agg_skb()` ignored a failed `usb_submit_urb()` result. Its
   `rtw_usb_txcb` and every original skb on `tx_ack_queue` then had no
   completion owner.
3. Reserved-page and H2C writes also relied on completion to free their skb,
   but returned a submission error without freeing it.
4. `rtw_usb_write_port_tx_complete()` ignored `urb->status`; a failed USB
   completion could enqueue a firmware TX-report wait or report ACK.
5. Submitted TX URBs were not anchored. Teardown destroyed the TX workqueue
   and continued freeing state without explicitly waiting for all TX callbacks.

Items 1--4 are fixed by upstream-series patch 7. The synthetic aggregate skb
is tracked and freed separately, so only original mac80211 frames enter status
or purge paths. Submission failures now release their caller-owned objects,
completion errors are reported to
mac80211 without ACK, and non-teardown TX URB errors have a cumulative,
rate-limited diagnostic. TX is not blindly replayed: an error completion does
not prove how much of an ambiguously submitted frame reached the adapter.
The injection harness validates counter uniqueness per adapter because each
`struct rtw_usb` owns its own counter and journal messages from the two devices
can interleave.

Item 5 is fixed by patch 8. Every TX URB is anchored before submission,
synchronously rejected URBs are unanchored, the TX producer is drained, and
`usb_kill_anchored_urbs()` completes every remaining callback before teardown
continues.

The callback guarantee also covers an URB that USB core has already removed
from the anchor list. In pinned Linux `315f4bd234b3`,
`__usb_hcd_giveback_urb()` suspends anchor wakeups before unanchoring, calls the
driver completion, then resumes wakeups. `usb_kill_anchored_urbs()` returns only
after both the URB list is empty and that suspended-wakeup count reaches zero.
The disposable test delays one selected-device completion for five seconds and
records both states immediately before and after the production kill call.

This lifetime design follows Linux v6.12
`Documentation/driver-api/usb/anchors.rst`: a USB driver must track submitted
URBs to cease interface I/O, successful completion automatically removes an
URB from its anchor, and `usb_kill_anchored_urbs()` forcibly finishes the
remaining anchored URBs.

## Static evidence

- A 2026-08-06 comparison with current Linux mainline found that mainline
  purges its TX-status queue after synchronous submission failure and frees a
  reserved/H2C skb on the corresponding error. However, the queue incorrectly
  includes the driver-owned synthetic aggregate skb. Mainline also returns
  false after that rejection, stops draining other queued frames, ignores
  `urb->status`, and has no TX URB anchor or synchronous callback teardown.
  The pinned mainline series therefore retains aggregate-buffer separation,
  continued queue draining, completion/error observability, and patch 8 while
  omitting reserved/H2C cleanup already present in the target.
- Linux v6.12 strict checkpatch on patches 7 and 8: zero errors, warnings, or
  checks. `MISSING_SIGN_OFF` is intentionally excluded because stored mail uses
  a neutral privacy identity and must be regenerated by the actual submitter.
- The two TX-only patches under `patches/mainline/` also pass the exact pinned
  Linux `315f4bd234b3` `checkpatch.pl`, spelling dictionary, and const-struct
  list with zero errors, warnings, or checks; only the intentionally absent DCO
  sign-off is excluded.
- `scripts/check-upstream-series.sh`: eight ordered patches apply with strict
  whitespace handling and reproduce `main.c`, `mac80211.c`, `usb.c`, and
  `usb.h` byte-for-byte.
- `tests/usb_tx_failure_injection.patch` applies exactly to production 0.1.5.
  It can inject a safe generic pre-submit `-EPROTO`, reject only a populated
  multi-frame aggregate before submission, or substitute `-EPROTO` at the
  driver's completion entry without shipping instrumentation. Each targeted
  aggregate rejection records its original-frame count and byte length. A
  corresponding marker is emitted only after the unchanged production error
  path frees the synthetic transfer skb and drains all original frames,
  proving that the corrected split-ownership cleanup ran. It also records
  queued-URB and active-callback anchor state immediately before and after the
  test build kills it during teardown.
- The exact pinned Linux `315f4bd234b3` `checkpatch.pl --strict` reports zero
  errors, warnings, or checks for the disposable TX instrumentation patch.
- Every hardware gate's kernel-event classifier recognizes
  `USB TX URB error`, so a functionally recovered interval cannot be accepted
  as transport-clean.

   and loaded source versions.

   fault, or leaked-work symptom.
4. Restore exact production 0.1.5 and repeat strict two-RTL8812AU churn plus
   the bidirectional checksummed transfer gate.
5. Keep synthetic results separate from the thermally clean physical USB path
   matrix; only the latter can attribute real `-71` events among driver,
   adapter, cable, hub/power, and host-controller causes.

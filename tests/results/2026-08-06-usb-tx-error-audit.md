# USB TX error and teardown audit — 2026-08-06

## Scope

This audit covers the RTL8812AU rtw88 USB transmit path after the validated
DKMS 0.1.4 symmetric mesh tests. It is source evidence for DKMS 0.1.5, not yet
hardware qualification of that version.

## Findings

The inherited TX path transferred skb/context ownership to an URB completion
callback but did not handle every path on which that callback cannot or must
not claim success:

1. `rtw_usb_tx_agg_skb()` ignored a failed `usb_submit_urb()` result. Its
   `rtw_usb_txcb` and every skb on `tx_ack_queue` then had no completion owner.
2. Reserved-page and H2C writes also relied on completion to free their skb,
   but returned a submission error without freeing it.
3. `rtw_usb_write_port_tx_complete()` ignored `urb->status`; a failed USB
   completion could enqueue a firmware TX-report wait or report ACK.
4. Submitted TX URBs were not anchored. Teardown destroyed the TX workqueue
   and continued freeing state without explicitly waiting for all TX callbacks.

Items 1--3 are fixed by upstream-series patch 7. Submission failures now
release their caller-owned objects, completion errors are reported to
mac80211 without ACK, and non-teardown TX URB errors have a cumulative,
rate-limited diagnostic. TX is not blindly replayed: an error completion does
not prove how much of an ambiguously submitted frame reached the adapter.
The injection harness validates counter uniqueness per adapter because each
`struct rtw_usb` owns its own counter and journal messages from the two devices
can interleave.

Item 4 is fixed by patch 8. Every TX URB is anchored before submission,
synchronously rejected URBs are unanchored, the TX producer is drained, and
`usb_kill_anchored_urbs()` completes every remaining callback before teardown
continues.

This lifetime design follows Linux v6.12
`Documentation/driver-api/usb/anchors.rst`: a USB driver must track submitted
URBs to cease interface I/O, successful completion automatically removes an
URB from its anchor, and `usb_kill_anchored_urbs()` forcibly finishes the
remaining anchored URBs.

## Static evidence

- A 2026-08-06 comparison with current Linux mainline found that mainline now
  purges an aggregate after synchronous TX submission failure and frees a
  reserved/H2C skb on the corresponding error. Source 0.1.5 follows that
  mac80211-aware ownership model while continuing to drain the software queue.
  Mainline still returns false after that synchronous rejection, stopping the
  worker before it drains other frames already queued by mac80211. It also
  ignores `urb->status` in the TX completion and has no TX URB anchor or
  synchronous TX-callback teardown. Therefore an actual mainline submission
  must omit the already-landed ownership cleanup, retain continued queue
  draining and the completion/error-observability delta, then apply patch 8
  after rebasing on the target tree.
- Linux v6.12 strict checkpatch on patches 7 and 8: zero errors, warnings, or
  checks. `MISSING_SIGN_OFF` is intentionally excluded because stored mail uses
  a neutral privacy identity and must be regenerated by the actual submitter.
- The two TX-only patches under `patches/mainline/` also pass the exact pinned
  Linux `315f4bd234b3` `checkpatch.pl`, spelling dictionary, and const-struct
  list with zero errors, warnings, or checks; only the intentionally absent DCO
  sign-off is excluded.
- `scripts/check-upstream-series.sh`: eight ordered patches apply with strict
  whitespace handling and reproduce `main.c`, `mac80211.c`, `usb.c`, and
  `usb.h` byte-for-byte.
- `tests/usb_tx_failure_injection.patch` applies exactly to production 0.1.5.
  It can inject a safe pre-submit `-EPROTO` or substitute `-EPROTO` at the
  driver's completion entry without shipping instrumentation. It also records
  whether the TX anchor was populated just before the test build kills it
  during teardown.
- Every hardware gate's kernel-event classifier recognizes
  `USB TX URB error`, so a functionally recovered interval cannot be accepted
  as transport-clean.
